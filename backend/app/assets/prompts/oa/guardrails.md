# 审查意见答复 · 总则与人审闸门（模块 D 横切）

以下「源规则（逐字）」为源 skill 原文，一字未改，是模块 D 的行为红线；其后为本平台的暂停点与配置适配说明。逐字段落中的「Obs 笔记」在本平台对应 OA 案例库记录。

## 源规则（逐字）

## 定位

可选、默认关闭。显式触发后进入：

1. **案例脱敏入库**（历史通知书/答复 → Obs 笔记；向量可选）  
2. **审查文档自动答复草稿**（先标签/字段过滤，向量可用时再相似度检索；须人审）

**不**替代专利代理签字与正式递交；产出为草稿。

## 禁止

- 未脱敏入库含客户名、电话、未公开核心参数的原文  
- 无检索命中（或未说明库为空）就长篇「糊弄」意见陈述  
- 修改超原申请记载范围却不标注风险  
- 无人审确认即将草稿当作已递交文件  
- 将 API Key 写入仓库或在回复中回显完整密钥

## 人审闸门

```
以下为审查答复【草稿】，须代理人/发明人复核后再递交。
请回复：确认仅作内部草稿 / 需要修改策略 / 暂停
```

## 平台暂停点说明（人审闸门的落地方式）

人审闸门在本平台由流水线引擎的 [PAUSE] 暂停态实现（暂停、表单与恢复由平台代码执行，不靠 prompt 询问）。模块 D 共四处强制暂停：

| 暂停点 | 阶段 | 人审内容 |
|--------|------|----------|
| P1 | D1 通知书结构化之后 | 用户核对结构化结果（条款、缺陷类型、条目划分、期限）——防条款幻觉的强制闸门 |
| P2 | D3 策略选项产出之后 | 用户逐条勾选答复策略（对应源规则「须人审」；修改超范围风险在选项中明示） |
| P3 | D5 汇总装配之后 | 终稿人审——采用上方「人审闸门」逐字话术作为确认文案，用户确认「仅作内部草稿」后才落盘交付 |
| P4 | D-ingest 案例入库前 | 用户核对案例笔记 frontmatter 与脱敏项清单，确认后才入库与向量化 |

草稿产物一律标注「草稿·须人工复核」；任何阶段不得生成可被误认为已递交文件的定稿表述。

## 配置适配说明（原「配置（对话交互 · 向量可选）」节）

- 原对话式 embedding 配置问答改为**平台设置页表单**（base_url / 模型 / 维度 / API Key），保存时服务端自动执行连通自检；
- 向量库构建、重建（rebuild）由服务端后台任务执行，重建前需用户在设置页确认；
- 向量检索超时或失败时**不中断流程**：服务端自动降级为标签/关键词检索，并在检索结果中明示 `retrieval_mode`（vector / tags_only / tags_fallback）——对应源规则「无检索命中就长篇糊弄」的防线：检索为空或库为空时，草稿只输出提纲与策略分析，并如实说明未引用历史案例；
- API Key 仅存于本机设置存储；任何 LLM 输出中不得回显完整密钥。
