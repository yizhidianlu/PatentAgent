# 专利解读 · 报告风格纪律（注入所有撰写调用）

以下纪律适用于解读报告全部章节的撰写。「源纪律（逐字）」为源 skill 原文，一字未改；其后为平台适配说明。

## 源纪律（逐字）

**标题纪律**：交付笔记的 `##` / `###` / callout 标题只用简洁名称（如「二、连贯叙事」「七、和现有技术的差别」），**禁止**加「（故事线）」「（若能从原文读出）」「（专利内依据）」等给 Agent 的说明。模板里「写作提示 · 勿写入交付稿」仅供撰写时参考，不得原样留在正文。

**实现痕迹禁令（硬性）**：交付笔记与库内索引**禁止**出现脚本/工具文件名（如 `*.py`）、流水线字段路径（如 `context_anchor.ipc_application`）、内部裁图文件名（如 `page_001_xref_01.png`）、Schema 合同名括号（如「结构说明（StructureSchema）」）及「由 `*_schema.json` 入库生成」类脚注。附录「来源」只写「离线 IPC 行业词表」等自然语言；附图说明只写「第 N 页」。结构/外观节标题用「结构说明」「外观要点」；连接关系「自/至」须为「件号 + 名称」。

**说明书段落依据（硬性）**：引用原文段落时写 **`说明书 0002`** 或区间 **`说明书 0002–0004`**（四位编号，用 en-dash `–`）。**禁止**再写裸 `[0002]`（Obsidian 会误染成假链接）。  

公开号、摘要须先检索核验；**禁止虚构**链接。

## 平台适配说明

1. **说明书段落引用**：一律写 `说明书 0002`，区间写 `说明书 0002–0004`（四位段落编号，区间用 en-dash `–`）；**禁止**写裸 `[0002]`。逐字段落中「Obsidian 会误染成假链接」的顾虑在站内同样成立——裸编号会被引用 lint 拦截（由平台代码执行）。段落号必须真实存在于本案说明书文本（服务端按段落号索引校验）。
2. **权项与附图引用**：正文可写「权2–3」「图1–3」；链接化与悬停预览由平台渲染层处理，撰写时不要自行加任何链接语法。
3. **标题纪律**：报告各节标题与 callout 标题只用简洁名称（如「二、连贯叙事」「七、和现有技术的差别」），禁止附加「（故事线）」「（若能从原文读出）」「（专利内依据）」等写给执行者的说明；模板「写作提示 · 勿写入交付稿」内容不得原样留在正文。
4. **实现痕迹禁令**：交付正文禁止出现脚本/工具文件名（`*.py`）、流水线字段路径（如 `context_anchor.ipc_application`）、内部裁图文件名（`page_001_xref_01.png`）、Schema 合同名括号（如「结构说明（StructureSchema）」）及「由 `*_schema.json` 入库生成」类脚注；附录「来源」只写「离线 IPC 行业词表」等自然语言；附图说明只写「第 N 页」；结构/外观节标题用「结构说明」「外观要点」；连接关系「自/至」须为「件号 + 名称」。
5. **检索与链接红线**：不得虚构任何 URL、公开号或检索结果；本平台解读模式不联网，涉及公开线索的内容一律标注「推断自公开文本，未联网核验」（见 grounding.md），且只能出现在第九、十节及 `callout-warning` 内，不得写入一至八节主结论。
6. **引用原文**：第四节权利要求原文引用块格式为「【{公开号}·权利要求{N}】{原文逐字片段}」；原文片段逐字照抄，不得改写。
