# 交底书自检 · 发明（Step 8 · AUDIT 调用）

## 任务

平台已注入组装后的交底书**全文**（发明）。按下列清单逐项核对；发现问题按文末契约输出修订补丁。自检结果用于修订正文，**不得**将自检清单或报告写入交底书任何章节。

## 8.1 逻辑与闭环（发明为主）

- [ ] 技术方案是否形成完整闭环（发现→处理→扩展/输出）？
- [ ] 模块之间关联关系是否清晰？上下游是否衔接？
- [ ] 分支样本（如边界样本、低置信度样本等）是否有明确处理路径？
- [ ] 依赖项（如类别中心、动态阈值等）是否有来源说明？
- [ ] **第五章「技术关键点」与第三章「系统流程」是否呼应？** 第五章以论点概述为主，技术细节在第三章；每条保护点须为可实施机制，**不是**仅罗列标题对象或「有三个××」。
- [ ] **3.1 对象与术语**：是否已按场景与参与者、标题对象如何进入系统、高频**领域词**定义三小段铺垫？
- [ ] **标题贯穿**：案件名称中的领域实词是否在 **3.2 框图、3.4 流程、第六章**作为同一执行主体出现，且未被更空的上位词替换？
- [ ] **术语贴合话题**：3.3 / 3.5 / 第五章用词，只看标题和 3.1 场景是否像本领域？若像另一技术领域（账本、指纹、水位、幂等、锚点等只是错位例，随案而变），是否已换成领域表述而非靠定义保留？机制是否仍说得清？
- [ ] **3.3 与 3.4 对应**：3.3 是否按框图拆成独立模块？3.4 正文是否逐项对应图中 S1—Sn（无漏步、无多步混成一段且不点序号）？
- [ ] **实施例**：是否有 2～3 个与 3.1/3.2 同名的实例（职责、能力、交付物、依赖），并覆盖主路径 + 一条第三章已有分支（而非 3.4 缩写）？

## 8.2 公式与参数一致性（发明；含公式时必做）

**Step 8 必做（含公式时）**：除符号体例与跨节一致外，须**主动复核公式是否正确、公式逻辑是否与第三章叙述一致**（等同用户会提出的「检查公式和公式逻辑是否有误，有误请调整」）；发现问题**直接给出修订补丁**，勿仅提示用户自行修改。

### 符号与体例

- [ ] **formula_plan（发明含公式）**：本案已有 formula_plan；`paradigm_ids`∈`references/formulas/paradigms.yaml`（及覆盖合并结果）；已通过平台公式复算校验或等价手检
- [ ] **符号表（3.4.1）**：全文含公式时是否已设 **3.4.1** 并 **先定义符号**（含义、下标、量纲）；式 (1) 及后文每个符号是否均已在表中定义？
- [ ] **维度下标**：是否存在 `^{cpu}`、`^{mem}`、`^{io}` 等 **上标表示维度** 的写法？若有须改为 `b_{i,\mathrm{cpu}}`、`a_{j,\mathrm{mem}}` 等 **下标 + `\mathrm{}`** 形式（见公式体例规则 **`invention/formula_style.md` §7.7**）
- [ ] **装饰音**：是否出现 `\tilde`/`\hat`/`\bar` 等？若有改为独立符号（如平滑量 \(A\)）或范式 `ema_smooth`
- [ ] **字母多义**：同一字母是否兼指任务侧与节点侧等不同对象？若有须拆分符号（如任务用 \(b\)、节点用 \(g\)）
- [ ] **公式表述一致**：同一物理量在不同公式、段落中是否 **同形同义**（如权重公式、调整系数、匹配分 \(s_{ij}\) 等）
- [ ] **LaTeX 体例**：行内/块级分隔符是否全文统一（`\(...\)`/`\[...\]` 或 `$`/`$$` 二选一）；块级公式是否尽量单行；是否避免 `\text{且}` 等易渲染失败写法
- [ ] **3.5 与符号表**：3.5 参数表「符号」列是否与 3.4.1 **逐字同形**
- [ ] **阈值范围**：与正文一致（如 0.5–1.5、0.8–1.2 等）
- [ ] **参数命名**：全文统一，避免同义不同名混用（公式符号与 **§8.1 场景术语**分开查：场景词换名须整族替换，见 merger / correction）
- [ ] **实施例数值**：与 3.5 关键技术参数对应，不冲突；且与 `formula_plan.numeric_example` 可互相印证

### 公式正确性与逻辑（必核）

- [ ] **式面正确性**：各式是否无明显笔误（运算符、括号配对、上下标错位、同一式内符号与符号表不符、缺项/多写项、指数或分母写错等）？
- [ ] **可算性**：平台已对 formula_plan 复算；代算失败须改式或改数值例。复算跳过的复杂式再用 `numeric_example`（或第六章同一组数）手算；算不出则改式或补定义（如 \(\sigma\)）
- [ ] **量纲常理**：相加各项是否已无量纲/归一？防零除 \(\varepsilon\) 是否与分母同量纲？有无裸 `max(1, 容量)`？
- [ ] **约束与不等式方向**：公式中的 `\leq`/`\geq`/正负号是否与文字含义一致（如「饱和度」「有余量」「限频间隔」等）；多条件「且/或」是否与 3.4 流程分支一致？
- [ ] **公式与流程互推**：3.4.1 主公式（含式 (1)）及衍生式，能否与 **3.4 流程说明**（各步骤 S1—Sn）、**3.3 模块职责** 逐步对应？叙述中的打分、重排、限频、窗口聚合等是否在公式中有体现，**无**「文字一套、公式另一套」？
- [ ] **边界与特殊情形**：空队列、单节点、分母为零、指标缺失、达到上下界等情形，公式或正文是否给出合理处理或说明（至少不与主公式矛盾）？
- [ ] **量纲与取值**：符号表声明的量纲/取值范围是否与公式用法一致（如权重为正、比例在 0—1、计数为非负整数等）？
- [ ] **修订联动**：若修正公式或逻辑，是否已同步改 **formula_plan**、**3.4 文字**、**3.5 参数**、**第六章实施例** 及 **3.4.1 符号表**（见 §7.7 跨节一致）？

## 8.3 格式与引用

- [ ] **图示**：系统框图与流程图均为 fenced mermaid，无 ASCII 框图；流程图节点若用 S1/S2 作 id，**可见标签须含该序号**（`S1["S1 …"]`，禁止 `S1[只写中文]`）；正文「如图/见图 N」与图对应
- [ ] 章节引用：如「详见 3.4.1」须指向真实存在的章节
- [ ] **1.1 / 在先对比**：列举的专利/文献/在先外观是否均附有**可访问且与著录项一致**的公开 URL（非编造）；是否与查新记录及检索说明自洽；**检索说明**是否**未**出现 `cnipa_epub_search.py`、WebSearch/降级等内部流程用语
- [ ] **查新摘要（国知局）**：凡检索命中中带非空 **`abstract`** 的条目，正文概括**是否体现对摘要的理解**；无 `abstract` 时是否已如实注明且未杜撰方案细节
- [ ] **文末清洁**：正文**无**技能仓库名、`examples/`、`disclosure_draft` 路径、「教学示例」「虚构」「不构成法律承诺」等**元信息脚注**（若存在则删除）

## 处理原则

发现问题则**直接给出修订补丁**。  
**公式类（发明）**：Step 8 须完成 §8.2 核对；有误则改公式并联动修订相关章节，**不要**只报告问题而不给补丁（缺少必要技术事实、无法从正文与材料推断正确写法的问题写入 `unresolved`）。  
**术语 / 标题贯穿 / 实施例（发明）**：§8.1 相关项不通过则改 3.1、框图、流程、实施例或第五章（以补丁形式给出）；换叫法须整族替换，机制不丢。

## 输出契约（仅输出一个 JSON 围栏块）

对未通过的检查项给出修订补丁；不要输出修订后全文，也不要输出自检报告正文。

```json
{
  "verdict": "pass",
  "patches": [
    {
      "checklist_item": "如「8.2 维度下标」——对应上文清单条目",
      "anchor_before": "补丁位置之前 10-40 字的原文锚点（逐字）",
      "original_excerpt": "被替换的原文片段（逐字，与全文完全一致）",
      "replacement": "替换后的文字",
      "reason": "修改原因（一句）"
    }
  ],
  "unresolved": ["无法自行修复的问题说明（缺技术事实等），由平台呈现给用户，不入正文"]
}
```

规则：

- `verdict`：全部通过为 `pass`（此时 `patches` 为空数组）；给出补丁为 `patched`。
- `anchor_before` 与 `original_excerpt` 必须为全文**逐字子串**（服务端按精确→模糊匹配应用补丁）；各补丁的 `original_excerpt` 之间不得重叠。
- 同一问题贯穿多处（如术语族替换、符号改名）时，逐处各出一条补丁，保持跨节同形。
- 公式类补丁会触发平台公式门禁复跑；术语类补丁会触发全文术语族替换核查。
