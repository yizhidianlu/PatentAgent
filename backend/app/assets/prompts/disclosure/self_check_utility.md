# 交底书自检 · 实用新型（Step 8 · AUDIT 调用）

## 任务

平台已注入组装后的交底书**全文**（实用新型）。按下列清单逐项核对；发现问题按文末契约输出修订补丁。自检结果用于修订正文，**不得**将自检清单或报告写入交底书任何章节。

（§8.1 中明显属「算法/系统/公式」而与本案结构主线无关的条目可跳过——与原清单选用表一致。）

## 8.1 逻辑与闭环（发明为主）

- [ ] 技术方案是否形成完整闭环（发现→处理→扩展/输出）？
- [ ] 模块之间关联关系是否清晰？上下游是否衔接？
- [ ] 分支样本（如边界样本、低置信度样本等）是否有明确处理路径？
- [ ] 依赖项（如类别中心、动态阈值等）是否有来源说明？
- [ ] **第五章「技术关键点」与第三章「系统流程」是否呼应？** 第五章以论点概述为主，技术细节在第三章；每条保护点须为可实施机制，**不是**仅罗列标题对象或「有三个××」。
- [ ] **3.1 对象与术语**：是否已按场景与参与者、标题对象如何进入系统、高频**领域词**定义三小段铺垫？
- [ ] **标题贯穿**：案件名称中的领域实词是否在 **3.2 框图、3.4 流程、第六章**作为同一执行主体出现，且未被更空的上位词替换？
- [ ] **术语贴合话题**：3.3 / 3.5 / 第五章用词，只看标题和 3.1 场景是否像本领域？若像另一技术领域（账本、指纹、水位、幂等、锚点等只是错位例，随案而变），是否已换成领域表述而非靠定义保留？机制是否仍说得清？
- [ ] **3.3 与 3.4 对应**：3.3 是否按框图拆成独立模块？3.4 正文是否逐项对应图中 S1—Sn（无漏步、无多步混成一段且不点序号）？
- [ ] **实施例**：是否有 2～3 个与 3.1/3.2 同名的实例（职责、能力、交付物、依赖），并覆盖主路径 + 一条第三章已有分支（而非 3.4 缩写）？

## 8.3 格式与引用

- [ ] **图示**：以 **`figure_plan`** 入文线稿为主（CAD/实拍不入文）；正文「如图/见图 N」与清单 `fig` 一致
- [ ] **figure_plan（实用/外观）**：本案已有 figure_plan；主题/材料若本轮有变，清单已重评（含 `relates_to`）；未入文图有 `reason`；总装+局部或入文多视时图际关联已填写
- [ ] 章节引用：如「详见 3.4.1」须指向真实存在的章节
- [ ] **1.1 / 在先对比**：列举的专利/文献/在先外观是否均附有**可访问且与著录项一致**的公开 URL（非编造）；是否与查新记录及检索说明自洽；**检索说明**是否**未**出现 `cnipa_epub_search.py`、WebSearch/降级等内部流程用语
- [ ] **查新摘要（国知局）**：凡检索命中中带非空 **`abstract`** 的条目，正文概括**是否体现对摘要的理解**；无 `abstract` 时是否已如实注明且未杜撰方案细节
- [ ] **文末清洁**：正文**无**技能仓库名、`examples/`、`disclosure_draft` 路径、「教学示例」「虚构」「不构成法律承诺」等**元信息脚注**（若存在则删除）

## 8.4 实用新型专项

- [ ] 文头 **专利类型：实用新型**
- [ ] 第三章可追溯 StructureSchema（部件/连接/布局）；`uncertain` 未写成既定公差
- [ ] 第五章为装置/结构书式，非纯方法独立点
- [ ] 未把外观美感或算法步骤当作构造创新主线
- [ ] 附图「如图 N」与 `figure_plan` 的 `fig`/`path` 一致（非散落 assets 临场挑选）
- [ ] 总装+局部入文时 `relates_to` 已写；正文「局部/剖视」表述与之对齐；跨图件号一致
- [ ] 入文图仅为合格 lineart；CAD/实拍未误入正文  
- [ ] 入文线稿件号与 `structure_schema.parts` 一致，引出线落点与部件对应；未混用外观线稿风格

## 处理原则

发现问题则**直接给出修订补丁**。  
**术语 / 标题贯穿 / 实施例（发明）**：§8.1 相关项不通过则改 3.1、框图、流程、实施例或第五章（以补丁形式给出）；换叫法须整族替换，机制不丢。

## 输出契约（仅输出一个 JSON 围栏块）

对未通过的检查项给出修订补丁；不要输出修订后全文，也不要输出自检报告正文。

```json
{
  "verdict": "pass",
  "patches": [
    {
      "checklist_item": "如「8.4 附图引用」——对应上文清单条目",
      "anchor_before": "补丁位置之前 10-40 字的原文锚点（逐字）",
      "original_excerpt": "被替换的原文片段（逐字，与全文完全一致）",
      "replacement": "替换后的文字",
      "reason": "修改原因（一句）"
    }
  ],
  "unresolved": ["无法自行修复的问题说明（缺技术事实等），由平台呈现给用户，不入正文"]
}
```

规则：

- `verdict`：全部通过为 `pass`（此时 `patches` 为空数组）；给出补丁为 `patched`。
- `anchor_before` 与 `original_excerpt` 必须为全文**逐字子串**（服务端按精确→模糊匹配应用补丁）；各补丁的 `original_excerpt` 之间不得重叠。
- 同一问题贯穿多处（如术语族替换、符号改名）时，逐处各出一条补丁，保持跨节同形。
- 公式类补丁会触发平台公式门禁复跑；术语类补丁会触发全文术语族替换核查。
