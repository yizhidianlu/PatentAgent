# 权利要求偏向点（§7.6 · 交付阶段 STRUCT 调用）

## 任务

平台已注入交底书**终稿全文**。产出**仅供用户选用**的「权利要求偏向点」交互选项（**不得**写入交底书正文；用户的选择仅存记录，不改正文）。仅输出一个 JSON 围栏块。

## 要求

1. 用户若希望对**第五章「技术关键点和欲保护点」**做更贴近**权利要求书撰写习惯**的强化，可**用一句话说明侧重点**。
2. 承接方式：平台按迭代流程（iteration/merger.md）以**当前交付稿为基准**合并，另存新版本交付。
3. **禁止捏造偏向**：对话里提出的「可对举的两类侧重点」**必须**能从**当前定稿与上游已用材料**中推出——包括 Step 2 材料摘要、Step 3–4 已选专利点、**第三至五章已写明的技术方案与保护点表述**；**不得**为了凑交互而编造本案未涉及的场景、模块或行业词。若全文仅有一条清晰保护主线，**只须忠实概括该主线**并询问是否改为更「方法/系统/流程步骤」或更「装置/模块」等**书式侧重**（仍须对应文中已有结构，不新增技术事实）。  
4. 在满足上条前提下，可给出**两组可对举的偏向**（用语须**摘编或概括**自正文已有概念，而非套用泛例）；呈现给用户的句式可参考：

> 若您希望权利要求/保护点表述更偏「……」或更偏「……」（**二者均须与本稿已阐述的技术路线或保护点一致，仅为书式或强调重心之择**），请说明侧重点；我可以以当前交付稿为基准另存一版，对**第五章做权利要求书式强化**（无新材料时其它章节以衔接一致为前提，尽量保持既有结论）。

**合并 / 纠正迭代**再次交付定稿时，平台仍会调用本模块产出同类引导（仍遵守「不捏造」）。

## 输出契约（仅输出一个 JSON 围栏块）

```json
{
  "groups": [
    {
      "axis": "该组对举的维度（如：方法流程侧重 vs 装置模块侧重）",
      "option_a": {"label": "偏向 A 的一句话表述", "basis_quote": "支撑该偏向的终稿原文摘录（逐字）"},
      "option_b": {"label": "偏向 B 的一句话表述", "basis_quote": "支撑该偏向的终稿原文摘录（逐字）"}
    }
  ]
}
```

规则：

- `basis_quote` **必须是终稿的逐字子串**（服务端做 substring 校验，不命中该组将被丢弃并要求重出）；摘录取能直接支撑该偏向的方案或保护点表述，10–60 字为宜。
- 全文仅有一条清晰保护主线时，只输出一组：两个选项为「方法/系统/流程步骤」与「装置/模块」等**书式侧重**之择（仍须对应文中已有结构，不新增技术事实）。
- 通常输出 1–2 组；捏造的组会因 basis_quote 校验失败被丢弃，故**宁少勿编**。
