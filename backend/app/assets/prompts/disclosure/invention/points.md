# 专利点挖掘与融合（Step 3–4 · 发明）

**本文件仅用于专利类型 = 发明（默认）。** 实用新型 / 外观的类型路由由平台处理。

## Step 3：候选专利点

- 列出 **3–5 个**候选专利点。
- 每个专利点需说明：
  - 技术背景
  - 创新点
  - 与现有技术区别（可先基于材料推断，查新后在第一章收紧）
  - 可实施性
- 可基于已有事实**适度推演**，但须有技术合理性支撑。

## Step 4：融合与选定

- 检查多个专利点是否可合并创新要素。
- 将相关技术点融合为**方法+系统**类专利（如适用）。
- 突出「组合创新」：若干要素有机结合形成的独创性方案。
- 选定的**工作标题**中的领域对象，须能在后续交底 **3.1 / 框图 / 流程 / 实施例**落地（见术语与标题贯穿规则 §7.9）；不要选事后只能写成空泛「系统/模块」的名称。

### 输出策略

**默认**：最终优先产出**最有价值的一篇**交底书。

若用户明确要求多篇：先在 `fusion_note` 列多篇大纲（标题 + 核心区别），由平台与用户约定撰写顺序。

### 选定依据

- 创新性、可授权性
- 与查新结果的差异化（查新完成后复核）
- 技术方案完整、可实施
- 保护范围合理

## 输出契约

先**流式输出候选点分析**（markdown，供用户阅读：每个候选按「技术背景 / 创新点 / 与现有技术区别 / 可实施性」展开），随后在**文末**输出一个 ```json 围栏块：

```json
{
  "candidates": [
    {
      "id": "P1",
      "title": "工作标题（含领域对象核心词）",
      "background": "技术背景（2-3 句）",
      "innovation": "创新点（2-3 句）",
      "distinction": "与现有技术区别（查新前可基于材料推断）",
      "feasibility": "可实施性说明（1-2 句）",
      "score": 0
    }
  ],
  "recommended": "P1",
  "fusion_note": "可融合候选与融合方式说明；无融合建议则空字符串"
}
```

规则：候选 **3–5 个**；`score` 为 0–100 的综合评分（创新性、可授权性、技术方案完整可实施、保护范围合理）；`recommended` 为建议选定（或融合后主推）的候选 id；用户将在平台界面勾选或要求融合后进入下一步。
