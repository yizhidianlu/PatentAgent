# 迭代 · 增量合并（GEN 调用）

## 前提（平台已代办）

平台已注入：当前定稿全文（或受影响章节）、本轮用户说明、新材料的消化摘要卡、术语表与 figure_plan（如有）。合并结果由平台写入**新时间戳文件**（禁止覆盖旧稿）并维护修订对话记录；你只负责按下列流程改稿与输出。

## 何时启用

由意图路由判定为 `merge` 时执行本流程：**在已有交底书或上一轮输出上补充新材料**（新文档、新代码说明、粘贴片段、扩展章节等），且以**合并进现有结构**为主时，**应**执行本流程；用户按「权利要求偏向点」交互仅要求**第五章权利要求书式强化**、已说明侧重点者，同样走本流程（合并范围以第五章为主）。**不要求**用户说出「迭代」等固定词；也**不必**先询问是否进入迭代模式。

## 流程

1. **识别增量**：新内容主要影响哪些章节：背景、1.1 现有技术、3.4 流程、实施例等；实用/外观还须判断是否影响**附图主题或材料集**。若用户指出某术语别扭、太抽象、与标题对不上，视为**术语族替换**（见下步），不要只当文风润色。
2. **非破坏性合并**：以**追加或局部重写**为主，不推翻未涉及且用户未要求修改的章节。
2a. **术语族替换（若本轮改叫法或自检发现话题错位）**：把与标题/3.1 场景不符的抽象行话，在 1.1、第二章、3.1–3.5、第四–六章及 mermaid 中**整族**改为领域表述；3.1 定义领域词及如何判定。禁止只改 3.3 一句。**不要**把某几个词写成全局禁词表（错位词随案而变）；也**不要**靠「先定义」把错位词留下，或借机写入本案材料没有的配置模块。
3. **figure_plan 同步（实用新型 / 外观，强制）**：本轮若新增/替换/删除附图，或主题/保护侧重点/部件与设计要点变化——本案**无** figure_plan 则按 `shared/fill_*_schema` 流程**创建**；**有**则重评 `relevance` / `quality` / `score`、`use_in_disclosure`、`fig`、`covers`、`relates_to`、`theme_summary`。**先**更新清单，**再**改正文插图与「如图/见图 N」。CAD 条不得改为入文。清单更新后如需补线稿由用户上传（v1 无线稿生成）。  
4. **查新联动**：若增量改变了技术实质，判断是否需要**补充检索**并更新 1.1 / 区别论述。
5. **一致性**：合并后对照自检清单（self_check_*）中的 **8.1（发明：标题贯穿/术语/实施例）、8.2、8.3**（实用/外观含 **8.4/8.5** 与 figure_plan 项）快速检查；若涉及 **3.4.1 公式/3.5 参数**，须同步核对 **formula_plan** 与公式体例规则（invention/formula_style.md §7.7）（范式库、符号表、维度下标、3.5 符号列同形）。若本轮做了术语族替换，§8.1 相关项必核。
6. **落盘**：合并后的全文交平台落盘为新时间戳文件（不覆盖旧稿），由平台完成。
7. **对话记录**：修订对话记录由平台自动追加，无须你输出。

## 输出（强制，不可省略）

在交付修改后的正文（或说明已写入路径）之后，**必须在同一条回复中**追加独立小节，**标题固定为**：

## 合并摘要（留档）

其下用 **3–6 句完整中文**，依次说明：**改了哪些章节**、**原因**、**是否影响保护点或检索结论**、**是否已做 8.1（若发明且涉及术语/标题/实施例）/8.2/8.3 核对**；实用/外观若动过图或主题，须点明 **`figure_plan` 是否已同步**。若做了术语族替换，点明新旧叫法及是否整篇对齐。  
若未输出本节，视为未完成本 prompt。

**定稿延续**：本轮合并结果作为交付定稿时，「权利要求偏向点」建议由平台在交付阶段以独立调用（invention/claim_bias.md）产出，本调用**不**输出该交互，也**不得**写入正文。

## 与「纠正」的区别

- **merger**：侧重新材料、新功能的**扩展**。
- **iteration/correction**：侧重用户指出**错误、风格或与事实不符**的修正。

## 输出顺序与元信息契约

1. 修改后的受影响章节全文（markdown；未受影响章节不要重写、不要输出）。
2. 「## 合并摘要（留档）」小节（格式与句数见上文，平台存档并展示）。
3. 文末**先**输出一个合并元信息 ```json 围栏块（服务端剥离，不入正文）：

```json
{
  "affected_chapters": ["3.4", "六"],
  "needs_search": false,
  "figure_plan_updated": false,
  "term_replacements": [{"old": "旧叫法", "new": "领域表述"}]
}
```

`needs_search`=true 表示增量改变技术实质、需补充查新（平台将触发补查新并回改 1.1）。随后按术语规则再输出 terms_delta 块。
