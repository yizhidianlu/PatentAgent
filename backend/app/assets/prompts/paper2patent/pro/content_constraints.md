# Content Constraints

## 一、语言与表达规范

**表达方式**：
- 使用技术性、客观性陈述句。
- 避免使用第一人称（"我"、"本发明"等在权利要求中应改为"所述"）。
- 避免使用主观评价性语言（"优秀的"、"卓越的"、"高效的"等）。
- 避免使用夸张性语言和广告性语言。

**句式结构**：
- 权利要求：短句为主，每个步骤简洁明确。
- 说明书：可使用复杂句式，但应当清晰易懂。
- 避免过长的句子，尽量使用主动语态。

**术语规范**：
- 优先使用所属技术领域的通用技术术语。
- 使用科技术语而非日常口语。
- 同一技术概念在整个文件中使用同一术语。

## 二、内容深度控制

**权利要求书**：浅层表达为主，避免过度详细。
- 权利要求1：核心方法框架，简要描述主要步骤。
- 权利要求2-3：对核心步骤进行中等详细程度的描述。
- 权利要求4+：逐渐细化至具体实现细节。

**说明书**：深度表达为主，充分公开技术方案。
- 技术背景：对现有技术进行充分调研和分析。
- 发明内容：详细说明技术方案和预期效果。
- 具体实施方式：详细到能够让普通技术人员实现。

## 三、结构层次控制

**权利要求书层次**：
```
第一层：独立权利要求（最宽保护范围）
    ↓
第二层：从属权利要求（中等保护范围）
    ↓
第三层：从属权利要求（较窄保护范围）
    ↓
第四层：具体实施例（最窄保护范围）
```

**说明书层次**：
```
【技术领域】→【技术背景】→【发明内容】→【附图说明】→【具体实施方式】
  简洁        三层展开      三层展开     逐一说明     详细到极致
```
